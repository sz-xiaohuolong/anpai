### 机器人互撞修复（2026-10-18 追加）— **已被下一节取代，仅存历史**

> 本节的 `reserved`（依次避让）方案**已被推翻**：它让机器人之间零碰撞，等于完美协同。
> 当前实现见下一节「机器人策略重写」。

**症状**：加 3 个机器人，它们每轮都选同一个位置，全部撞车。

**根因（结构性错误，不是调参问题）**：`chooseSlot(state)` 原本只是**公开状态的纯函数**。
同一局的机器人看到的是同一份公开局面，纯函数必然给出**同一个答案**——确定性 + 相同输入 = 必然撞车。
「上一轮拥挤度」这一项对同局所有机器人也是同一份数据，因此每一轮都会撞。

**修复**：
- `chooseSlot` 增加 `reserved` 参数，登记「本轮已被其它机器人预定的位置」，权重 3。
- 房主浏览器**依次**决策，逐个累积 `reserved` 并传入。
- 登记占位在任何 `await` 之前**同步**完成，避免两个定时器并发时读到同一份未更新的预定表。

**证据**：

| 检查 | 结果 |
|---|---|
| `pnpm test` | **119 passed**，新增「1 真人 + 3 机器人打满 8 轮，机器人从不互撞」 |
| `scripts/e2e-bot.mjs` B 部分 | **零碰撞**，8 轮机器人占位 `[7,6,4] [5,2,3] [7,6,4] [1,5,2] [7,6,3] [4,5,2] [7,6,1] [3,4,5]`，三者被罚次数全为 0 |
| `scripts/e2e-room.mjs` | 14/14 |

**顺带修掉的测试缺陷**：`e2e-room.mjs` 原本用固定 `sleep` 对齐 5 秒轮间间隔，机器负载高时会漏轮，
表现为随机失败（一次实测掉到 8/14）。已改为「轮询等到本轮真正进入提交阶段再操作」。

### 机器人策略重写：均衡抽样（2026-10-18 追加，取代上一节）

**症状（上一版引入的新问题）**：`reserved` 方案让三个机器人**从不互撞**——它们每轮稳稳各占一位、
全部拿满分，而真人要独自承担所有撞车。真人做不到这种协同，这是在作弊。

**根因**：把「机器人互撞」当成 bug 修，修过头了。机器人需要的是**不被利用**，不是**互不干扰**。

**当前模型**：按 `docs/game-balance-v1.md` §2 的**对称混合策略均衡**概率抽样（闭式解）。

- `chooseSlot(state, { seatId, roomCode })`，不再有 `reserved` 参数。
- 种子 = `房间码 : 席位 : 轮次`，FNV-1a + 雪崩混合映射到 [0,1)，再按均衡分布逆变换抽样。
  **房间码必须参与种子**：只用 (席位, 轮次) 时每局落点组合被固定，等于一次抽样重复上千次，
  实测撞车率掉到 37%（真人基线 69.1%）——机器人比真人更少撞车，同样占了便宜。
- 仍是无随机源、无时钟的纯函数，因此测试可直接断言、结果可复现。

**证据**：

| 检查 | 结果 |
|---|---|
| 三张表 vs 文档 §2.2 | 3/4/5 人**逐位吻合**：`3.4 3.4 13.6 21.1 26.9 31.7` / `3.1 3.1 10.1 10.1 15.4 15.4 19.6 23.1` / `2.8 2.8 8.1 8.1 8.1 12.2 12.2 12.2 15.5 18.3`；解析撞车率 58.8% / 69.1% / 77.1% 亦吻合，**无死位** |
| 3000 局 × 4 机器人 × 8 轮模拟 | 回合级撞车率 **67.6%**（真人基线 69.1%）、单人每轮被罚 **39.1%**（基线 40.3%）、人均 8 轮总分 **35.3**（基线 35.2） |
| `pnpm test` | **126 passed / 9 files**（`tests/bot.spec.ts` 15 条） |
| `pnpm typecheck` / `pnpm build` | 通过；90.24 kB JS / 13.65 kB CSS |
| `scripts/e2e-bot.mjs` | **11/11**，B 部分 8 轮落点 `[[2,7,2],[3,4,7],[1,5,1],[5,7,2],[3,3,6],[1,3,5],[4,6,6],[2,4,7]]`——4/8 轮各占一位、4 轮有人撞车，双向断言均成立 |
| `scripts/e2e-room.mjs` | **14/14**（回归，未受影响） |

**公平性回归怎么守住的**：`tests/bot.spec.ts` 的 `simulateFourBots(600)` 同时断言
「不是永远互撞」（撞车率 > 0.55）与「不是永不互撞」（撞车率 < 0.82、被罚率 > 0.28），
单人被罚率与人均总分都钉在真人基线区间内。**两个方向都挡**，避免再次修过头。

**顺带修掉的 E2E 脆弱性**：`e2e-bot.mjs` 的 A 部分原本用固定 `sleep` 对齐异步事件，
已全部改为条件轮询（`waitFor`，超时打印卡在哪一步）；「机器人席位不存在」时提前退出，
不再抛 `TypeError` 掩盖真因。与上一轮 `e2e-room.mjs` 的修法一致。
排查过程中确认了一个**环境陷阱**：`pnpm build` 会触发 `wrangler dev` 重载 worker 并打断进行中的房间，
表现为「A 部分停在 LOBBY、B 部分正常」这种像 flaky 的确定性失败。已记入「环境与操作备忘」。

**未验证**：`src/app/useRoom.ts` 里「房主浏览器调 `chooseSlot`」这段改动**没有在真实浏览器里跑过**，
证据是类型检查 + E2E 复刻同样的调用方式。真实浏览器路径见「已知缺口 8」。

## 本次实施中发现并修正的问题

1. **规则文档 §8 的被罚次数写错。** 小北应为 4（第 3、4、5、6 轮），原文写 3。已修正文档与 fixture。
2. **`tick()` 丢状态更新。** 原实现用「有没有产生事件」判断是否返回新状态；「整局结束」分支只改状态不产生事件，导致 `phase` 永远停在 `settled`。已改为比较 state 引用。
3. **PartyServer 路由名写错。** 路由是 `/parties/:绑定名-kebab-case/:房间`，即 `/parties/anpai-room/<房间码>`，不是 `/parties/room/...`。
4. **零提交的回合被判为已结算。** `project()` 里「全员已揭示」在 `commits` 为空时是空真，
   导致刚开的回合立刻结束。已改为「提交阶段关闭后才可能结算」，并加回归测试。
5. **最后一轮结算后 5 秒内点「再来一局」会被静默拒绝。** 房间此时仍是 `settled` 而非 `over`。
   已放宽为「`settled` 且已打满 8 轮」也允许重开。
6. **游戏中刷新页面会卡在房间页。** `RoomView` 的跳转 watcher 没有 `immediate`，且对 `GAME_OVER`
   也会误跳。已改为只在「进行中」阶段跳转并加 `immediate`。
7. **E2E 测试被持久化状态污染。** 房间码写死导致 DO 状态跨运行累积，读出历史日志里的旧 `ROUND_OPEN`。已改为每次生成唯一房间码。

## 环境与操作备忘

### 本地开发怎么跑

```bash
# 终端 1：房间服务
pnpm dev:room          # wrangler dev，127.0.0.1:8787

# 终端 2：前端
pnpm dev               # vite，5173
```

Vite 已配置 `/parties` 的 WebSocket 代理到 8787（见 `vite.config.ts`），因此浏览器里
`location.origin` 可以直接用作房间地址，不需要额外配环境变量。

```bash
# 端到端（需先起 dev:room）
pnpm e2e
# 也可以指定走 Vite 代理：
ANPAI_ORIGIN=http://localhost:5173 pnpm e2e
```

- **`wrangler dev` 在本机沙箱下需要覆盖 `HOME`**：它硬编码写 `~/Library/Preferences/.wrangler`，沙箱拒绝后会直接退出。绕过方式：`HOME=<可写临时目录> npx wrangler dev`。
- **DO 状态会持久化在 `.wrangler/state`**（已 gitignore）。测试用固定房间码会读到历史日志。
- **TypeScript 固定在 5.9**：`vue-tsc@3.3.13` 依赖 TS 的 `./lib/tsc` 子路径导出，TS 7 已移除，升级会导致 `typecheck` 崩溃。
- **不要在 `wrangler dev` 运行时紧接 `pnpm build` 跑 E2E**：重建 `dist/` 会触发 worker 重载，
  把正在进行中的房间打断。实测表现是 A 部分停在 `LOBBY` 或机器人 `JOIN` 丢失，
  而 B 部分（重载之后才连接）正常——**看起来像随机 flaky，其实是确定性环境干扰**。
  `pnpm build` 后等几秒再跑 E2E，或先跑 E2E 再 build。
