## 0. 排期原则

**按「失败成本」排序，不按「功能依赖」排序。**

这个项目最大的风险不是技术做不出来，而是**做出来不好玩**。所以：

- 最便宜、最能证伪核心假设的事排在最前面（阶段 0 纸笔，零代码）。
- 最贵、最容易返工的事排在假设被验证之后（阶段 4 揭示动画、阶段 6 部署）。
- 纯逻辑（阶段 1）先于任何网络与 UI，因为它是唯一需要密集测试的部分，而且它没有外部依赖，可以完全独立地做完做对。

**总计约 6 个阶段 + 2 个前置/收尾，预计 3–5 个工作日的实际投入**（AI 辅助下）。这不是承诺，是量级参考。

## 阶段 0 · 纸笔验证（不写代码）

**这是硬性前置门槛。** 详细方案见 [game-balance-v1.md](./game-balance-v1.md) §7。

| 任务 | 产出 |
|---|---|
| 0.1 组织 4 人，用纸片玩一局 8 轮，基础价值 `4,4,5,5,6,6,7,8` | 五个指标记录表 |
| 0.2 换 1.5× 极差数值 `4,4,5,5,5,6,6,6` 再玩一局 | 同上 |
| 0.3 用表现更好的那组再玩一局，重点观察玩家是否在利用历史 | 同上 |

**验收标准（通过则进入阶段 1，不通过则先改数值）：**

| 指标 | 通过线 |
|---|---|
| 玩家能说出「我为什么选这个位置 + 我认为别人会怎么选」的轮次占比 | **≥ 50%** |
| 结束后想再来一局的人数 | **≥ 3/4** |
| 单人 8 轮被罚次数中位数 | **≤ 4** |
| 最高价值位与最低价值位的被选次数之比 | **≥ 1.5** |
| 单轮中位耗时 | **≤ 90 秒** |

> **如果第 1 项不达标**：不要进入开发。这说明核心还没到「读懂对手」的层次，加机制也救不回来。先回到数值与规则重新设计。
>
> **如果第 3 项不达标**（被罚太频繁）：先压极差到 1.5×，再考虑加位置数。
>
> **如果第 5 项不达标**（太慢）：把提交时限从 30 秒压到 20 秒，或轮数从 8 降到 6。

## 阶段 1 · 骨架 + 纯规则引擎

**目标：在完全不碰网络与 UI 的情况下，把规则引擎做到可证明正确。**

| # | 任务 | 优先级 | 验收标准 |
|---|---|---|---|
| 1.1 | `git init`，Vite + Vue 3 + TS + Tailwind 脚手架，ESLint + Vitest | P0 | `npm run dev` 出空白页；`npm test` 可跑 |
| 1.2 | 加 ESLint 规则：`src/core/**` 禁止 import Vue / DOM / 网络模块 | P0 | 故意在 core 里 import vue，lint 报错 |
| 1.3 | 加 ESLint 规则：禁止 `Math.random` / `Date.now` / `performance.now` 出现在 `src/core/rules.ts` | P0 | 故意写入，lint 报错 |
| 1.4 | `core/events.ts`：事件类型定义 | P0 | 类型可编译 |
| 1.5 | `core/values.ts`：三张基础价值表 + 极差断言 | P0 | 单测断言三张表极差均 ≤ 2.0× |
| 1.6 | `core/rules.ts`：`project(log) → GameState` | **P0** | 见下方断言集 |
| 1.7 | `core/log.ts`：按 `seq` 排序、去重、缺口检测 | P0 | 打乱顺序输入，投影结果与顺序输入相同 |
| 1.8 | 示例对局 fixture + 回放断言 | P0 | 用规则文档 §8 的 8 轮对局作 fixture，断言最终分数 `36/29/35/41` |

**1.6 的断言集（这是本阶段的核心交付）：**

1. 独占一个位置 → 得「基础价值 + 累积赏金」
2. 2 人选同一位置 → 两人各得 0
3. 3 人选同一位置 → 三人各得 0
4. 无人选择的位置 → 赏金 +1
5. 连续两轮无人选择 → 赏金 +2（累加，非重置为 1）
6. 赏金被独占取走后 → 归零
7. 撞车后 → 赏金保留且不增长
8. 同一份日志投影两次 → 结果深比较相等（**这条是整个架构的地基**）
9. 8 轮后 → 状态为 `GAME_OVER`，排名正确
10. 平局 → 按「最后一次独占轮次更晚者胜」裁决；从未独占者排最后

**阶段 1 完成定义：** `npm test` 全绿，且 `src/core/` 能在 Node 里直接 import 运行，不依赖任何浏览器 API。

## 阶段 2 · commit-reveal + 房间服务

**目标：两个浏览器能进同一个房间，完成一次「提交 → 揭示」的往返，且服务器不知道任何人选了哪个位置。**

| # | 任务 | 优先级 | 验收标准 |
|---|---|---|---|
| 2.1 | `core/crypto.ts`：`commit()` / `verify()`，用 WebCrypto | P0 | 通过架构文档 §5.2 的 **3 个测试向量**，逐字节相等 |
| 2.2 | `party/server.ts`：房间对象骨架 | P0 | 本地 `wrangler dev` 起得来 |
| 2.3 | 服务器：分配 `seq`、广播事件、`(author, clientSeq)` 去重 | P0 | 同一事件发两次，只入日志一次 |
| 2.4 | 服务器：成员与在线状态、`JOIN` / `LEAVE` | P0 | 开两个标签页，双方都看到对方在线 |
| 2.5 | 服务器：`ROUND_OPEN`（写入 `openedAt`）、按截止发 `ROUND_TIMEOUT` | P0 | 提交截止 30 秒后自动发超时事件 |
| 2.6 | `net/client.ts`：WebSocket 客户端 + 自动重连 | P0 | 断网 5 秒后自动重连成功 |
| 2.7 | 席位：`seatToken` 生成、`seatId` 派生、`localStorage` 持久化、单连接接管 | P0 | 两个标签页用同一 `seatToken`，旧的被断开 |
| 2.8 | **服务器无规则断言** | P0 | 代码审查：`party/server.ts` 中不出现任何分数、赏金、位置语义 |

**阶段 2 完成定义：** 两个浏览器能各自提交并揭示，双方投影出的局面一致；服务器日志中不含任何位置明文。

## 阶段 4 · 揭示体验（最贵的部分，放在假设验证之后）

**目标：揭示那一秒有张力，且不拖沓。**

| # | 任务 | 优先级 | 验收标准 |
|---|---|---|---|
| 4.1 | `RevealOverlay.vue` 四拍结构：落牌 → 翻牌 → 记分 → 赏金 | **P0** | 全程 ≤ 4 秒（用 Performance API 断言） |
| 4.2 | 落牌：牌背图标错落落下，间隔 80ms | P0 | 不揭示任何内容 |
| 4.3 | 翻牌：`rotateY` 翻转 + `collided` 抖动 + `empty` 赏金弹跳 | P0 | 用 `cubic-bezier(0.2,0.8,0.2,1)` |
| 4.4 | 记分：分数点飞向记分板 + 数字滚动 | P1 | 撞车玩家显示 `—` 标记 |
| 4.5 | **跳过**：任意时刻点击立即到结算结果 | **P0** | 连打第二局时不会被动画卡住 |
| 4.6 | `prefers-reduced-motion` 降级为淡入，总时长 1.5 秒 | P1 | 系统开启该选项后动画降级 |

## 阶段 5 · 边界与异常

**目标：把「断线是常态」这件事真正做对。**

| # | 任务 | 优先级 | 验收标准 |
|---|---|---|---|
| 5.1 | 重连：拉全量日志 → 重放 → 恢复状态 | **P0** | 手机锁屏 30 秒后解锁，自动回到正确状态 |
| 5.2 | 重连中的轻提示（非弹窗） | P0 | 顶部显示「重连中…」，不遮挡操作 |
| 5.3 | 提交阶段重连：已有 `COMMIT` 不得被覆盖 | **P0** | 单测断言重复提交被忽略 |
| 5.4 | 揭示阶段超时未揭示 → 作废 + 弃权 + 不占位 | **P0** | 单测覆盖；该位置若因此空置，赏金 +1 |
| 5.5 | 零提交轮次 → 全员弃权后正常推进 | P0 | 单测覆盖 |
| 5.6 | 乱序 / 重复 / 缺口日志的处理 | P0 | 打乱日志后投影结果不变 |
| 5.7 | 席位掉线但不移出游戏 | P0 | 一人断线，其余人继续，轮次照常推进 |

**阶段 5 完成定义：** 手动做以下破坏测试全部通过——中途关标签页再打开、手机锁屏、开两个标签页抢同一席位、所有人不提交让轮次超时。

## V1 完成定义（Definition of Done）

- [ ] 3–5 人能通过一条链接进房，无需注册、无需安装
- [ ] 8 轮完整对局，10–20 分钟
- [ ] 撞车、赏金、结算全部正确（reducer 单测全绿）
- [ ] 同一日志投影两次结果相等（确定性断言通过）
- [ ] 服务器代码中不含任何游戏规则
- [ ] 任何人关页面 / 切后台，其余人继续，重连后能回到正确状态
- [ ] commit-reveal 三个测试向量通过
- [ ] 至少 3 台真机在移动网络下连通
- [ ] 真人对局后 ≥ 3/4 人愿意再来一局

## 明确不做（V1 范围外）

注册登录与账号体系 · 陌生人匹配与排行榜天梯 · 预测层与读心分数 · 撞车后的二级博弈 · 技能卡/道具/角色能力 · AI 玩家 · 聊天与语音 · 复杂动画与 3D · 商业化功能 · 观战模式 · 对局回放分享 · 多语言

**发现必要的新机制时，作为建议单独列出，不直接加入 V1。**

## 建议清单（不进 V1，供你决策）

| # | 建议 | 为什么有价值 | 为什么先不做 |
|---|---|---|---|
| S1 | **预测层 / 读心分数**：每轮额外暗选「我赌某对手会选哪」，猜中 +1 | 把「读懂对手」从口号变成可得分的东西；且能直接缓解「动作层随机化」的天花板。外部评审认为这是最酷的版本 | 增加一个输入与一套计分，违反「60 秒讲清规则」；且应在核心循环被验证好玩之后再叠加 |
| S2 | **撞车分级**：2 人撞与 3 人撞区别对待 | 5 人局 77% 回合级撞车率下，分级能提供更细腻的风险梯度 | 增加规则复杂度；当前玩家级被罚中位数只有 3，问题不紧迫 |
| S3 | **跨局性格档案**：局间自动生成「你落后时 73% 选中间位」 | 免费记账最值钱的产物；朋友局的话题度来源 | 需要跨会话持久化与统计，V1 明确不做 |
| S4 | **1.5× 极差作为正式数值** | 撞车率再降 5–9 个点，分差降约 1 分 | 会削弱揭示时刻的赌注感；先按阶段 0 的对照结果决定 |
| S5 | **追赶机制**（如落后玩家额外赏金） | 缓解「第 3 轮锁定败局」的风险 R4 | 违背「只靠读人取胜」的设计意图；先看真实分差曲线再定 |
