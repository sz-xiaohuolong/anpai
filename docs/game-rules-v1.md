## 1. 一句话规则

每轮所有人**同时秘密选一个位置**；某个位置只有你一个人选，你拿走它的分数；有两个人以上选了同一个位置，**这些人都拿 0 分**。8 轮后总分最高者获胜。

## 2. 基本参数

| 项目 | 值 |
|---|---|
| 玩家人数 | 3–5 人 |
| 每局轮数 | **固定 8 轮** |
| 位置数 | 玩家人数 × 2（3 人 6 格 / 4 人 8 格 / 5 人 10 格） |
| 目标时长 | 10–20 分钟 |
| 胜负 | 8 轮后总分最高者获胜 |
| 平局 | 见 §9.3 |

**规则复杂度目标：60 秒内解释清楚。** 因此 v1 不引入技能卡、道具、角色能力、预测层、二级博弈。

## 3. 位置与基础价值

位置是每轮争夺的目标，每个位置有一个**公开的、不对称的**基础价值。

| 人数 | 位置数 | 基础价值（低 → 高） | 极差 |
|---|---|---|---|
| 3 人 | 6 格 | 4, 4, 5, 6, 7, 8 | 2.0× |
| 4 人 | 8 格 | 4, 4, 5, 5, 6, 6, 7, 8 | 2.0× |
| 5 人 | 10 格 | 4, 4, 5, 5, 5, 6, 6, 6, 7, 8 | 2.0× |

- 位置**没有名字**，只有编号（位 0 … 位 N-1）和价值。v1 不加主题化命名，避免玩家被名字误导。
- **价值极差必须 ≤ 2.0 倍**。这是硬约束：极差越大，玩家越向高价值位集中，撞车率越高，且会出现「均衡概率为 0」的死位置。详见 [game-balance-v1.md](./game-balance-v1.md)。
- 以上数值是**测试参数**，不是最终平衡结果。调参时只改数字，不改结构，且必须维持极差 ≤ 2.0 倍。

## 4. 空位赏金（V1 核心机制）

**规则：**

1. 某位置本轮**无人选择** → 该位置赏金 **+1**，**无论它本轮是否已经带有赏金**（连续空置 N 轮 → 赏金 +N）。
2. 赏金**逐轮累积，不设上限**（8 轮内单个位置赏金上限为 7）。
3. 某位置被**恰好 1 人**选走 → 该玩家获得「基础价值 + 累积赏金」，随后该位置赏金**归零**。
4. 某位置出现**多人撞车** → 本轮不发放收益，赏金**保留但不增长**。

**该位置本轮的有效价值** = 基础价值 + 累积赏金。有效价值对所有人公开可见。

**设计意图：** 让每轮的价值地形都在变化，迫使玩家不断重新评估，而不是固定盯着最高的那一格。低价值位会作为「蓄水池」积累赏金，后期反而比初始最高价值位更值钱——这是本作最主要的一个涌现策略层。

## 5. 一局的状态机

```
LOBBY ──全员准备──▶ ROUND_OPEN ──▶ COMMITTING ──▶ REVEALING ──▶ RESOLVING
                        ▲                                            │
                        │                                     轮数 < 8 │ 轮数 = 8
                        └────────────────────────────────────────────┤
                                                                     ▼
                                                                 GAME_OVER
```

| 状态 | 含义 | 进入条件 | 离开条件 |
|---|---|---|---|
| `LOBBY` | 房间等待，玩家进出、准备 | 房间创建 | 全员准备且人数 ≥ 3 |
| `ROUND_OPEN` | 本轮开始，公布本轮有效价值 | 上一轮结算完成，或开局 | 产生 `ROUND_OPEN` 事件 |
| `COMMITTING` | 收集暗选提交 | `ROUND_OPEN` | 全员提交 或 提交截止 |
| `REVEALING` | 公布选择、校验承诺 | 提交阶段结束 | 全员揭示 或 揭示截止 |
| `RESOLVING` | 结算得分与赏金 | 揭示阶段结束 | 结算完成 |
| `GAME_OVER` | 最终排名 | 第 8 轮结算完成 | — |

**关键约束：状态的推进由事件驱动，不由任何单一客户端「说了算」。** 见 [game-architecture-v1.md](./game-architecture-v1.md)。

## 6. 每轮详细流程

### 6.1 开始轮次

1. 任意客户端追加 `ROUND_OPEN { round, openedAt }` 事件。
2. 界面公布本轮每个位置的**基础价值、累积赏金、有效价值**。
3. **提交截止时间 = `openedAt` + 30 秒**（`openedAt` 来自日志，不由本地时钟决定）。

### 6.2 提交阶段（COMMITTING）

1. 玩家点选一个位置。
2. 客户端本地生成 `nonceHex`（16 字节随机数，小写十六进制 32 字符）。
3. 计算承诺：

   ```
   commit = SHA-256( UTF8( roomId + "|" + round + "|" + seatId + "|" + slotIndex + "|" + nonceHex ) )
   ```

4. 客户端**只广播 `commit`**，不广播位置。界面进入「已提交，等待其他玩家」。
5. 提交后**不可更改**（因为承诺已入日志）。v1 不提供「取消提交」。

**承诺同时绑定房间与席位**，因此同一份 `(轮, 位, nonce)` 在不同房间或不同玩家处产生不同哈希，防止跨房间/跨玩家重放。

### 6.3 揭示阶段（REVEALING）

1. 触发条件：**全员已提交** 或 **提交截止时间到**。
2. 触发后，**提交截止 + 15 秒**为揭示截止。
3. 每个已提交的玩家广播 `REVEAL { slotIndex, nonceHex }`。
4. 其他人校验：用 §6.2 的同一编码重算 `commit`，与日志中该玩家的 `commit` 比对。
   - 一致 → 该玩家的选择被接受。
   - 不一致 → 该玩家的选择**作废**，本轮弃权（见 §9.1）。

### 6.4 结算（RESOLVING）

对每个位置按**选择该位置的人数**结算：

| 该位置的选择人数 | 结果 |
|---|---|
| 恰好 1 人 | 该玩家得「基础价值 + 累积赏金」；该位置赏金**归零** |
| ≥ 2 人 | 这些玩家本轮**各得 0 分**（不淘汰、不扣分）；该位置价值不发放，赏金**不变** |
| 0 人 | 该位置赏金 **+1** |

**结算顺序无关紧要**：每个位置的结算互相独立，不存在「先到先得」。这是刻意的设计——避免出现「谁先提交谁赢」的时序依赖。

### 6.5 公布与历史

结算后向所有玩家展示：

- 每个人选择了哪个位置（**永久公开**）
- 哪些位置发生撞车、撞了几人
- 每个人本轮获得多少分
- 各玩家累计得分与当前排名
- 所有位置**下一轮**的基础价值、赏金与有效价值

历史以「玩家 × 轮次」矩阵保留**完整 8 轮**，不截断、不延迟。

## 7. 计分

- 玩家分数是**累加值**，只增不减。撞车不得分，但**不扣分**。
- 单轮单玩家最高得分 = 该位置基础价值 + 累积赏金（理论上限 8 + 7 = 15）。
- 一局总分 = 8 轮得分之和。

## 8. 完整计分示例

**4 人局 · 8 轮 · 基础价值 `4,4,5,5,6,6,7,8`**（下例为一次真实模拟的完整对局，算术已校验）

| 轮 | 本轮有效价值 | 结果 | 结算后分数（阿元/小北/Kai/老周） |
|---|---|---|---|
| 1 | 4,4,5,5,6,6,7,8 | 老周独得位4(+6)、Kai独得位5(+6)、阿元独得位6(+7)、小北独得位7(+8) | 7 / 8 / 6 / 6 |
| 2 | 5,5,6,6,6,6,7,8 | 老周独得位1(+5)、小北独得位6(+7)、**阿元+Kai 撞位3** | 7 / 15 / 6 / 11 |
| 3 | 6,4,7,6,7,7,7,9 | 老周独得位5(+7)、Kai独得位6(+7)、**阿元+小北 撞位4** | 7 / 15 / 13 / 18 |
| 4 | 7,5,8,7,7,6,7,10 | Kai独得位0(+7)、老周独得位2(+8)、**阿元+小北 撞位6** | 7 / 15 / 20 / 26 |
| 5 | 4,6,5,8,8,7,7,11 | 老周独得位3(+8)、阿元独得位4(+8)、**小北+Kai 撞位5** | 15 / 15 / 20 / 34 |
| 6 | 5,7,6,5,6,7,8,12 | 阿元独得位5(+7)、Kai独得位6(+8)、**小北+老周 撞位1** | 22 / 15 / 28 / 34 |
| 7 | 6,7,7,6,7,6,7,13 | 四人各占一位、**无人撞车**：老周位1(+7)、小北位2(+7)、阿元位4(+7)、Kai位6(+7) | 29 / 22 / 35 / 41 |
| 8 | 7,4,5,7,6,7,7,14 | 小北独得位0(+7)、阿元独得位6(+7)、**Kai+老周 撞位4** | **36 / 29 / 35 / 41** |

**最终排名：** 1. 老周 41 · 2. 阿元 36 · 3. Kai 35 · 4. 小北 29（总分 141）

**从这一局能读出的东西：**

- **位7 的赏金一路涨到 14 有效价值**（基础 8 + 赏金 6），因为前 7 轮几乎没人敢碰它——它是「显而易见的陷阱」。这就是赏金机制在起作用。
- **位4 在第 8 轮的有效价值只有 6**（基础 5 + 赏金 1），却让 Kai 和老周撞在一起，两人各丢一轮。
- 四人被罚次数：阿元 3、小北 4、Kai 3、老周 2——中位数 3，与模型预测吻合。
- 老周全程没有连续两轮被罚，这是他能领先的关键；不是因为运气最好，而是因为他在位1/位2/位3 之间轮换，避开了高价值位的拥挤。

## 9. 特殊情况与边界规则

### 9.1 提交了但未揭示

**规则：该玩家的提交作废，本轮弃权，得 0 分，且不占任何位置**（因此该位置可能触发赏金 +1）。

**为什么这条规则是安全的：** 它使「故意拒绝揭示」成为**弱劣势策略**——

- 若你独自占位：揭示 → 得分；拒绝 → 得 0。所以你揭示。
- 若你与对手都占位：揭示 → 两人都 0；拒绝 → 你的承诺作废，**对手变成独占并得分**。所以你仍然揭示。

两种情况你都拿 0，但揭示能阻止对手得分。因此理性玩家永远会揭示。残留的只有「故意送分给朋友」式的 kingmaking，这是所有多人游戏共有的社交问题，不是协议漏洞。

### 9.2 截止时间

| 阶段 | 截止时间 |
|---|---|
| 提交 | `ROUND_OPEN.openedAt` + 30 秒 |
| 揭示 | 提交截止 + 15 秒 |

- 截止时间由**日志中的 `openedAt`** 推导，不由任何客户端本地时钟决定，因此所有人重放日志得到同一截止时间。
- 任意客户端在截止后追加 `ROUND_TIMEOUT { round, phase }` 事件，阶段即可合法推进。
- 若一轮**零提交**：`ROUND_OPEN` 仍然存在，因此截止时间可推导，该轮全员弃权后正常进入下一轮。

### 9.3 平局

1. 先比较「最后一次成功独占位置的轮次」，**更晚者胜**。
2. 若一方**从未**独占过任何位置，则其名次排在所有至少独占过一次的玩家之后。
3. 若仍相同，**并列**，不设加时赛。

### 9.4 掉线与重连

- 身份由 `seatToken`（存于 `localStorage`）绑定，**不是昵称**。同一昵称可以是不同席位。
- 掉线后重进 = 拉取日志 → 按规范全序排序 → 去重 → 重放，恢复到当前状态。
- 重连时：提交阶段可继续提交（已有承诺不得覆盖）；揭示阶段若未到截止可正常揭示；回合已推进则直接进入当前轮，错过的轮次按已记录的弃权结算。
- **房主退出不影响游戏**：不存在房主。任何客户端关闭页面或切后台，其余人继续。

### 9.5 重复事件与乱序事件

- 事件去重键为 `(round, seq, author)`。
- 任何客户端在投影前，先按 `(round, seq, author)` 字典序排序，因此不同到达顺序得到同一局面。
- 检测到日志缺口（同一 `author` 的 `seq` 不连续）时，先补齐再投影，补齐前不推进回合。

### 9.6 规则判定的确定性要求

**所有判定必须是追加式事件日志上的纯函数。** 判定逻辑中禁止使用 `Math.random`、`Date.now`、`performance.now`。

- 随机性只出现在两处，且都在**客户端本地**：`nonceHex` 的生成、以及（如有的）本地 AI 提示。
- 时间只作为**协调**依据，其结论必须以 `ROUND_TIMEOUT` 事件的形式进入日志，才算「判定」。

## 10. V1 明确不做

注册登录、账号体系、陌生人匹配、排行榜天梯、预测层与读心分数、撞车后的二级博弈、技能卡/道具/角色能力、AI 玩家、聊天与语音、复杂动画与 3D、商业化功能。

**发现必要的新机制时，作为建议单独列出，不直接加入 V1。**
