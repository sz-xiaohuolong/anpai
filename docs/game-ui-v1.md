## 1. 设计定位

**一句话：深色牌桌上的纸牌。**

不是后台管理系统，也不是炫技的游戏官网。整个界面只服务一件事——**让玩家在一秒内看懂「哪个位置现在值多少分」，并且在揭示那一秒感到紧张。**

**移动端优先。** 朋友局的真实场景是：一个人把链接丢进群聊，其他人掏出手机点开。桌面端是次要场景（可能是同一个人用电脑开一局看回放）。所有布局先按 375px 宽设计，再向上适配。

## 2. 视觉语言

### 2.1 配色

深色桌布 + 浅色纸牌。**高对比靠明度，不靠饱和色**，这样在手机低亮度下也读得清。

| 角色 | 值 | 用途 |
|---|---|---|
| `--felt` | `#101310` | 桌面底色（近黑微绿，模拟牌桌） |
| `--felt-raised` | `#191D18` | 面板、抽屉 |
| `--hairline` | `#2B3129` | 分隔线、卡片边框 |
| `--card` | `#F4F0E6` | 位置卡片底（暖纸白） |
| `--card-ink` | `#1A1A17` | 卡片上的主文字 |
| `--card-ink-dim` | `#6B6A62` | 卡片上的次要文字 |
| `--text` | `#E9EDE6` | 深色底上的正文 |
| `--text-dim` | `#8B9288` | 深色底上的次要文字 |
| `--bounty` | `#E8A33D` | **赏金**。全局唯一的高饱和色，只用于赏金 |
| `--capture` | `#4FA97A` | 独占成功 |
| `--collide` | `#D2564F` | 撞车 |
| `--focus` | `#7FB2E8` | 键盘焦点环 |

**赏金是全局唯一的强调色。** 因为赏金是本作唯一「每轮都在变」的信息，它必须一眼可见。基础价值用墨色，赏金用琥珀色，两者的区别是颜色 + 位置双重编码。

### 2.2 字体

| 用途 | 字体 | 说明 |
|---|---|---|
| 数字（价值、分数、轮次） | `"Archivo", system-ui` 字重 700，`font-variant-numeric: tabular-nums` | 数字必须等宽，否则结算时数字跳动会很难看 |
| 中文正文 | `"Noto Sans SC", "PingFang SC", system-ui` | |
| 拉丁正文 | `"Inter", system-ui` | |

**不使用衬线体。** 这是个数字游戏，数字的清晰度优先。

### 2.3 间距与圆角

- 间距刻度：`4 / 8 / 12 / 16 / 24 / 32 / 48`（px）
- 卡片圆角 `10px`，面板圆角 `14px`
- 触控目标最小 `44×44px`
- 按钮不用胶囊形。用 `8px` 圆角的矩形——更克制，也更适合密集的卡片布局。

### 2.4 动效原则

- **只有揭示阶段允许超过 300ms 的动画。** 其余所有过渡 ≤ 180ms。
- 揭示全程 ≤ **4 秒**，且**任何时刻可点击跳过**（点击后直接跳到结算结果）。
- 尊重 `prefers-reduced-motion`：开启时用淡入替代位移与缩放，总时长压到 1.5 秒。

## 3. 核心组件：位置卡片

**这是整个游戏最重要的组件。** 玩家的每一个决策都发生在这张卡上。

### 3.1 信息层级

卡片上只有一个「大数字」，其余都是解释：

```
┌──────────────────────┐
│  位 7                │  ← 位置编号，11px，--card-ink-dim
│                      │
│        14            │  ← 有效价值，40px/700，--card-ink（最大的元素）
│                      │
│  基础 8   +6 赏金     │  ← 18px；「+6 赏金」用 --bounty，基础值用 --card-ink-dim
└──────────────────────┘
```

**为什么把「有效价值」而不是「基础价值」做成最大数字：** 玩家的决策依据是有效价值。基础价值和赏金是它的解释。如果反过来，玩家会盯着不变的数字看，而忽略每轮都在变的赏金——那正好是核心机制失效的路径（见 [game-balance-v1.md](./game-balance-v1.md) 风险 R2）。

**赏金为 0 时**，第三行只显示「基础 8」，不留空位，避免出现「+0 赏金」这种噪音。

### 3.2 卡片的六种状态

| 状态 | 视觉 | 触发 |
|---|---|---|
| `idle` | 纸白底，可点 | 提交阶段，未选 |
| `selected` | 纸白底 + `--focus` 2px 内描边 + 右上角一枚背面朝下的牌背图标 | 我点了它 |
| `locked` | 纸白底降到 60% 不透明，覆盖「已锁定」小字 | 已提交，等待他人 |
| `captured` | 绿色左边条 4px + 底部显示独占者昵称 + `+N` 分数 | 揭示后，恰好 1 人 |
| `collided` | 红色左边条 4px + 底部列出所有选择者 + `0` | 揭示后，≥2 人 |
| `empty` | 整卡降到 35% 不透明 + 赏金处显示 `+1` 并闪烁一次 | 揭示后，无人选择 |

**不依赖颜色单独传达信息**：`captured` / `collided` / `empty` 除颜色外各有文字标签和图标形状（✓ / ✕ / ○），色盲玩家可辨。

### 3.3 卡片网格

| 位置数 | 手机（< 640px） | 桌面（≥ 640px） |
|---|---|---|
| 6 格 | 2 列 × 3 行 | 3 列 × 2 行 |
| 8 格 | 2 列 × 4 行 | 4 列 × 2 行 |
| 10 格 | 2 列 × 5 行 | 5 列 × 2 行 |

手机端 2 列固定：卡片宽度约 160px，在 375px 屏上单卡高度约 112px，10 格时总高 5×112 + 间距 ≈ 600px——加上顶栏和记分板，需要滚动。**这是可接受的**：玩家在提交阶段只需要看到并点选一个格子，滚动一次不是问题。揭示阶段会自动滚动到发生事件的位置。

## 4. 页面清单

### 4.1 首页 `/`

```
┌─────────────────────────────────────┐
│                                     │
│              暗 牌                   │   ← 40px/700
│   8 轮，8 个位置，谁在骗谁？           │   ← 15px，--text-dim
│                                     │
│  ┌───────────────────────────────┐  │
│  │  昵称                          │  │
│  └───────────────────────────────┘  │
│                                     │
│  ┌───────────────────────────────┐  │
│  │        创建房间                │  │   ← 主按钮，--bounty 底
│  └───────────────────────────────┘  │
│                                     │
│  ┌──────────┐  ┌────────────────┐   │
│  │ 房间码    │  │   加入         │   │   ← 次按钮
│  └──────────┘  └────────────────┘   │
│                                     │
│  ▸ 60 秒看懂规则                     │   ← 可折叠
└─────────────────────────────────────┘
```

**折叠的规则说明**（展开后 ≤ 4 行 + 一个小图示）：

> 每轮所有人**同时秘密选一个位置**。
> 只有你一个人选 → 你拿走它的分数。
> 两个人以上选了同一个 → **这些人都拿 0 分**。
> 没人选的位置，下轮**赏金 +1**，越来越值钱。

图示：三个小人同时指向两个格子，其中两个指向同一个格，那个格上打红叉。

**昵称持久化**在 `localStorage`，回访时预填。昵称允许重复（身份由 `seatToken` 绑定，见 [game-architecture-v1.md](./game-architecture-v1.md)）。

### 4.2 房间等待页 `/room/:code`

```
┌─────────────────────────────────────┐
│  ← 退出                             │
│                                     │
│  房间码                             │
│  A N P A I 7 K          [复制链接]   │   ← 24px/700，字间距加大
│                                     │
│  玩家 (3/5)                         │
│  ┌───────────────────────────────┐  │
│  │ ● 阿元           已准备        │  │
│  │ ● 小北           等待中        │  │
│  │ ○ Kai            离线          │  │
│  └───────────────────────────────┘  │
│                                     │
│  ┌───────────────────────────────┐  │
│  │        准备 / 取消准备          │  │
│  └───────────────────────────────┘  │
│                                     │
│  满 3 人且全部准备后自动开始          │   ← 12px，--text-dim
└─────────────────────────────────────┘
```

**没有房主**，因此没有「房主点开始」。规则是：**人数 ≥ 3 且全员已准备 → 自动开局**。这样任何人关掉页面都不会卡住其他人。

`[复制链接]` 复制的是带房间码的完整 URL（`https://…/room/ANPAI7K`），方便直接丢进群聊。

### 4.3 核心游戏页 `/room/:code/play`

```
┌─────────────────────────────────────┐
│  第 3 / 8 轮          提交中   ⏱ 18s │   ← 顶栏，倒计时环
├─────────────────────────────────────┤
│                                     │
│  ┌────────┐  ┌────────┐             │
│  │  位 0   │  │  位 1   │             │
│  │    6   │  │    5   │             │
│  │ 4  +2  │  │ 4  +1  │             │
│  └────────┘  └────────┘             │
│  ┌────────┐  ┌────────┐             │
│  │  位 2   │  │  位 3   │             │
│  │    7   │  │    6   │             │
│  │ 5  +2  │  │ 5  +1  │             │
│  └────────┘  └────────┘             │
│         …（共 4 行）…                │
│                                     │
├─────────────────────────────────────┤
│  阿元 22  小北 15   Kai 28   老周 34  │   ← 记分板，可横向滚动
│                        [ 历史 ]      │
└─────────────────────────────────────┘
```

**顶栏**：
- 轮次进度：`第 3 / 8 轮`，下方一条 8 段的细进度条
- 阶段标签：`提交中` / `揭示中` / `结算中`
- 倒计时：环形进度 + 秒数。**≤ 5 秒时环变 `--collide` 色**，并在 `prefers-reduced-motion` 关闭时轻微脉冲

**记分板**：固定在底部，显示昵称 + 累计分。当前玩家高亮。超过 4 人时横向滚动。

**历史抽屉**：点「历史」从底部升起，显示「玩家 × 轮次」矩阵：

```
        R1   R2   R3   R4   R5   R6   R7   R8
阿元    位6  位3✕ 位4✕ 位6✕ 位4  位5  位4  位6
小北    位7  位6  位4✕ 位6✕ 位5✕ 位1✕ 位2  位0
Kai     位5  位3✕ 位6  位0  位5✕ 位6  位6  位4✕
老周    位4  位1  位5  位2  位3  位1✕ 位1  位4✕
```

- `✕` 标记撞车轮次
- 每人一行，位置编号等宽对齐
- 当前轮次列高亮

**这是前提 3 的承重 UI**（「读懂对手」）。它必须让人一眼看出「小北前四轮都在高位区」「老周从没连续被罚」。因此：**行内用色块标出高位/低位**，而不是只给数字——让偏好模式在视觉上直接浮现。

### 4.4 揭示与结算（覆盖层，不是独立路由）

**这是整个游戏最重要的体验时刻。** 分四拍，总时长 ≤ 4 秒：

**第 1 拍（0.6s）· 落牌**
每个玩家的选择以一枚牌背图标出现在对应位置卡片上。牌背图标错落落下（每枚间隔 80ms）。此阶段**不揭示任何内容**，只有「谁选了几个位」的压力。

**第 2 拍（1.2s）· 翻牌**
所有牌背同时翻转。用 `transform: rotateY(180deg)`，`cubic-bezier(0.2, 0.8, 0.2, 1)`。
- `captured` 卡片：绿色左边条滑入，独占者昵称淡入，卡片轻微上浮 2px 再落回
- `collided` 卡片：**红色左边条快速闪两下**，卡片左右抖动 3px（各 120ms），列出所有选择者
- `empty` 卡片：整卡降透明，赏金 `+1` 琥珀色数字弹一下（scale 1 → 1.25 → 1）

**第 3 拍（0.8s）· 记分**
每个得分玩家的分数从卡片飞向底部记分板对应昵称（一个圆点位移 + 淡出），记分板数字滚动到新值。撞车玩家记分板不变化，但昵称旁出现一个短暂的 `—` 标记。

**第 4 拍（1.4s）· 赏金更新**
所有位置的赏金数字更新到下一轮的值。上涨的赏金用琥珀色闪一次。然后进入下一轮。

**跳过**：任意时刻点击屏幕 → 立即跳到第 4 拍结束后的状态。**这个跳过热区必须存在**——连打多局时玩家不会想每轮都看 4 秒动画。

### 4.5 对局结束 `/room/:code/result`

```
┌─────────────────────────────────────┐
│              最终排名                │
│                                     │
│   1   老周            41            │   ← 冠军行用 --bounty 左边条
│   2   阿元            36            │
│   3   Kai             35            │
│   4   小北            29            │
│                                     │
├─────────────────────────────────────┤
│  本局统计                            │
│  被罚次数      老周 2  其余各 3       │
│  最高单轮      小北 +8（第 1 轮）     │
│  最高赏金      位 7 涨到 14          │
│  无人问津最久   位 0（连续 6 轮）     │
├─────────────────────────────────────┤
│  ┌─────────────┐  ┌──────────────┐  │
│  │  再来一局    │  │  返回房间     │  │
│  └─────────────┘  └──────────────┘  │
└─────────────────────────────────────┘
```

**「本局统计」里的四条都是刻意选的**：它们把玩家在局中感受到但说不清的东西（赏金涨了多少、谁一直被罚）变成可读的事实。这直接服务「读懂对手」——让玩家赛后能复盘自己的模式。

**再来一局**：保留同一批席位与昵称，重置分数与赏金，回到等待页。**这是「连打多局」的主路径**，必须一步到位，不能要求重新分享链接。

## 5. 响应式与可访问性

### 5.1 断点

| 断点 | 布局变化 |
|---|---|
| `< 640px` | 卡片 2 列；记分板固定底部；历史抽屉全屏 |
| `640–1024px` | 卡片 3–4 列；记分板固定底部 |
| `≥ 1024px` | 卡片单行排布（8 格 = 4×2，10 格 = 5×2）；记分板移到右侧竖排；历史抽屉变为右侧面板 |

### 5.2 可访问性清单

- 触控目标 ≥ 44×44px
- 所有状态不只靠颜色：`captured`/`collided`/`empty` 各带 ✓ / ✕ / ○ 图标
- 键盘可达：卡片是 `role="radio"` 的 `radiogroup`，方向键移动、空格选中
- 焦点环使用 `--focus`，2px，`outline-offset: 2px`
- 倒计时到 5 秒时有**文字提示**，不只靠颜色变化
- `prefers-reduced-motion: reduce` → 揭示动画降级为淡入，总时长 1.5 秒
- 对比度：卡片墨色文字对纸白底 ≥ 12:1；深色底上的正文 ≥ 7:1

### 5.3 手机端特别注意

- **`<meta name="viewport">` 禁止缩放**：`user-scalable=no`——因为双指缩放会干扰卡片点选。但字号必须足够大，不能靠缩放补救。
- **防止误触**：提交后卡片立即进入 `locked`，且**不提供取消**。点击卡片后有 300ms 的视觉确认（描边）才真正提交，避免滑动时误触。
- **切后台不断线**：因为判定在客户端 + 日志可重放，切后台回来后自动重连并重放。UI 需要在顶部显示一个「重连中…」的轻提示，而不是弹窗。

## 6. 待确认的 UI 决策

| # | 决策 | 我的建议 | 需要你确认 |
|---|---|---|---|
| U1 | 位置是否给主题化命名（如「银行」「码头」） | **不给**。数字编号避免名字暗示价值，也省掉一套美术 | 是 |
| U2 | 揭示动画是否默认全播 | **默认全播，但保留跳过**；连打第二局起记忆「已看过」并缩短到 1.5 秒 | 是 |
| U3 | 是否显示「本轮有多少人已提交」 | **显示数量，不显示是谁**。显示「3/4 已提交」制造压力，但暴露具体人名会泄露信息 | 是 |
| U4 | 历史抽屉默认展开还是收起 | **默认收起**，但每次结算后自动高亮「刚结束的这一列」 | 是 |
| U5 | 手机端 10 格需要滚动，是否改成一屏放下 | **不改**。缩小卡片会牺牲数字可读性，而数字可读性优先于「一屏」 | 是 |
